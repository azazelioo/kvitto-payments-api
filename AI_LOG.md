# Работа с ИИ

Пользовался Codex, модель GPT-6.1 Sol, уровень рассуждений — лёгкий

Задание делал по частям: сначала разобрал PDF, потом перешёл к базе, расчётам, API и тестам. Docker и CI добавил после основных функций. В контекст передавал задание, текущий код и AGENTS.md. После изменений просил запускать pytest и ruff

## Примеры запросов

Формулировки ниже сокращены, смысл запросов сохранён

- «Разбери PDF: что обязательно, что даёт бонусы и где есть неоднозначности. Для каждого пункта напиши, как его проверить. Пока ничего не меняй»
- «Сделай идемпотентность: первый запрос с ключом возвращает 201, повтор — 200 и тот же платёж. Добавь UNIQUE в БД и rollback после конфликта. Проверь одновременные запросы с отдельными сессиями»
- «Добавь запуск через Docker Compose. Миграции должны выполняться перед сервером, SQLite храниться в volume. Проверь, что платёж остаётся после пересоздания контейнера»

## Что пришлось поправить

Сначала агент начал работать не в той папке. По pwd и git status заметили, что открыта другая директория, и продолжили в нужном репозитории

Ещё агент предложил не запускать приложение без WEBHOOK_SECRET. Для необязательной проверки подписи это было лишним условием. Оставили запуск без секрета, а при заданном секрете сделали подпись обязательной. Это поведение описано в README

Ruff находил проблемы форматирования. Один запуск CI упал на проверке формата Python-примера в README, до pytest очередь не дошла. После исправления проверку повторили, итоговый CI на коммите 3db3472 прошёл

При повторной проверке была ошибка уже в проверочном скрипте: он сравнивал платёж с исходным pending, хотя вебхуки перевели его в refunded. Исправили ожидаемый статус и проверили, что после пересоздания контейнера сохранились все поля

## Что проверено

На повторной проверке 6 октября прошли 229 тестов, ruff check, ruff format --check и проверка совместимости зависимостей. Осталось предупреждение Starlette об использовании httpx в TestClient, его не скрывали

Кроме тестов выполнили 52 проверки запросами к работающему API: суммы и промокоды, рассрочки на 3/6/12 месяцев, статусы, ошибки, фильтры и 12 одновременных запросов с одним ключом. Дублей не появилось, запрещённый переход не менял запись

Проверили оба способа запуска из README: Docker Compose и локально через Alembic и Uvicorn. Платёж сохранился после пересоздания контейнера. На отдельном сервере проверили HMAC: без подписи, с неверной подписью и изменённым телом — 401, с корректной подписью — 200 и новый статус в БД
